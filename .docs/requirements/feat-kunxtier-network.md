# kunxtier 组网与连通性

## 背景

kunxtier 是自研轻量 P2P 虚拟组网工具, 定位 ZeroTier / EasyTier 的平替: 现有方案不是功能不行, 而是用起来别扭——根节点慢、自建繁琐、审批与管控割裂、缺少开箱即用的管控面。核心中继 (`kunxtier relay`) 是网络的中枢与唯一权威: 一个核心中继可承载多张互相隔离的网络组, 每张网络有独立的成员、地址段与策略; 核心中继同时承载信令与内置密文转发。卫星中继 (`kunxtier relay --satellite`) 是用户按需自部署的纯转发扩展, 可多个, 不感知网络概念。relay + daemon 即闭环。设备大多位于 NAT 之后, 数据面采用 WireGuard 协议, P2P 直连优先。

## 目标

- 任意两台已注册节点在虚拟网内可以通过虚拟 IP 互访 (ping / TCP / UDP)
- 节点间流量优先 P2P 直连; 对称 NAT、机房出口等打不通的场景, 自动或按策略走中继 (核心内置或卫星), 无需手工配置
- 每个节点获得稳定的虚拟 IP, 重启后保持不变
- 新节点加入后, 其他在线节点自动感知并更新路由, 无需重启
- 一条命令起核心中继即可开网; 需要就近部署或带宽分担时, 加卫星中继即可水平扩展转发能力
- 一个核心中继可承载多个网络组 (不同圈子 / 环境天然隔离), 网络间完全隔离; 只用一个网络时无感知 (init 自动建默认网络)
- 空闲链路不断: NAT 映射与长连接由保活机制维持, 挂机后首包即通

## 用户流程 / 页面结构

### 设备上线 (daemon 视角)

1. daemon 启动, 读取本机 state (节点身份、节点凭证与 WireGuard 私钥)
2. 以节点凭证通过核心中继的挑战应答校验, 建立信令通道, 上报公钥与当前候选地址
3. 从核心中继获取本网络节点表 (含对端公钥)、中继列表与路径策略
4. 通过信令与对端交换候选地址, 并发发起 UDP 打洞
5. 打洞成功则使用直连; 失败则经中继建立转发

### 路径选择

1. 默认策略 "自动": 直连优先, 打洞超时自动回落中继 (从核心中继分发的中继列表中按序 / 就近选择, 列表含核心内置转发)
2. 节点级策略 "强制中继": 不尝试打洞, 全部流量直接经中继 (适用于出口不稳定、打洞反复失败等场景)
3. 策略在 Web 控制台配置 (见 feat-kunxtier-console), 核心中继经信令下发生效

### 连接维持

1. 直连路径默认开启 WireGuard persistent keepalive, 维持 NAT 映射
2. 中继路径与信令通道使用应用层心跳, 超时判定链路死亡并触发切换 / 重连
3. 中继列表内的目标按序尝试, 失败即切换下一个 (核心内置转发始终在列表末位兜底)

## 功能要求

| 编号 | 说明 | 验收标准 |
| ---- | ---- | -------- |
| FR-1 | 节点注册后由核心中继在其所属网络内分配 /32 虚拟 IP (每网独立 /16, 取自 100.64.0.0/10, 按创建顺序递增, 建网可显式指定段) | 分配结果持久化, 节点重启后 IP 不变; 不同网络地址段不重叠 |
| FR-2 | 节点间通过信令交换候选地址并发起 UDP 打洞 | 双端受限锥形 NAT 场景可建立直连 (e2e 提供真实 NAT 拓扑验证) |
| FR-3 | 自动策略下打洞失败自动回落中继 | 回落动作在超时阈值内完成, 无需用户干预 |
| FR-4 | 中继路径只转发 WireGuard 密文, 不持有任何会话密钥 | 卫星中继进程不存在可解密节点流量的密钥材料与管理数据 |
| FR-5 | 节点上下线事件实时同步给其他在线节点 | 对端在秒级窗口内更新 peer 列表与路由 |
| FR-6 | 直连与中继路径可自动切换与恢复 | 直连中断后流量切到中继; 直连恢复后切回直连 |
| FR-7 | 核心中继重启后节点自动重连并恢复全网状态 | 无需节点与卫星重启, 恢复后互通如初 |
| FR-8 | 路径状态可通过 CLI 与 Web 控制台查询 | 均输出每个对端的当前路径 (direct / relay) 与所用中继 |
| FR-9 | 卫星中继为纯转发扩展角色, 以可复用的 relay 令牌向核心注册, 保持注册长连接 | 新增卫星后列表自动分发给节点, 无需重启任何一方 |
| FR-10 | 节点级强制中继策略 | 设置后该节点不发起打洞、流量全走中继; 取消后恢复自动策略 |
| FR-11 | 网络组间完全隔离 | 不同网络的节点互不可达、成员列表互不可见, 令牌跨网无效 |
| FR-12 | 网络组管理 (创建 / 列表) | 网络创建后即可签发该网令牌, 无需重启核心中继 |
| FR-13 | 节点单网络归属 (MVP) | 一个 daemon 同时只属于一个网络; 多 membership 为后续演进 |
| FR-14 | 本地网段冲突检测: daemon 启动时检测本机接口与路由是否与所属网络 /16 重叠 (运营商 CGNAT 常用 100.64.0.0/10) | 冲突时拒绝启动, 报错包含诊断信息与处理建议 (换网段重建网络或调整本地网络) |
| FR-15 | 链路保活: 直连默认 persistent keepalive (25s 量级); 中继与信令通道应用层心跳 | 空闲 30 分钟后首次发包不黑洞、不触发重新打洞 |
| FR-16 | MTU 策略: TUN MTU 按最坏路径 (中继上 WG + TLS + TCP 叠加封装) 推导默认值; 大 UDP 分片行为明确定义 | 直连与中继路径下, 1400 字节级 ICMP 与大文件 TCP 传输均正常 |
| FR-17 | 节点生命周期: 节点名网内唯一; 重装 (state 丢失) 即新节点, 旧条目由 admin 移除; 节点移除后 IP 回收, 设复用保护窗口 | 同名注册被拒并提示; 移除后的 IP 在保护窗口内不分配给新节点 |
| FR-18 | 卫星生命周期: 与核心保持注册长连接, 断连即从列表摘除并全网更新 | 卫星死亡后, 回落流量在窗口内切换到下一个中继或核心内置转发 |

## 边界与约束

- 首发平台为 macOS、Linux 与 Windows
- 双侧均为对称 NAT 等打洞必然失败的拓扑, 走中继, 不视为缺陷
- 首发不做按用户 ACL, 全网节点互通; 属主为标注字段 (见 feat-kunxtier-access)
- 一个网络恰好归属一个核心中继 (唯一管理权威), 一个核心中继可承载多个网络组; 卫星中继可多个, 永不持有管理数据且不感知网络概念
- 虚拟网为 IPv4; IPv6 数据面为后续演进
- "远程访问内网" 指访问运行在节点上的服务; 经节点转发访问其所在物理网段 (子网路由) 为后续阶段功能

## 非目标

- 网内名称解析 (DNS / hosts 注入); 名字到 IP 的查询由 status 与控制台承载
- 子网路由 / 出口网关 (把节点背后整个物理内网暴露进虚拟网)
- L2 以太网仿真
- 按用户或按标签的细粒度 ACL
- 移动端 (iOS / Android) 客户端
- 一个节点同时加入多个网络 (多 membership)
- 网络组删除 / 停用 (低频操作, SQLite 保留数据, 后续按需补)
- 多核心中继组网与故障切换
