# kunxtier Web 控制台

## 背景

现有方案的管控体验是核心痛点: ZeroTier 审批与管控割裂, EasyTier 缺少开箱即用的管控面。kunxtier 把所有端的状态与治理收敛到一个轻量 Web 控制台。控制台是纯体验层: 无状态、无存储, 全部能力来自核心中继开放的 admin API, 部署在哪都行; relay + daemon 不开控制台也完全闭环。

## 目标

- 两种等价入口: 浏览器直接打开核心中继托管页面, 或在任意机器用 `kunxtier console --relay` 起本地控制台
- 全网状态一目了然: 节点在线状态、当前路径 (direct / relay)、所用中继
- 日常管控全部覆盖: 网络、用户、令牌、节点、路径策略、卫星中继
- 状态与 CLI / API 完全一致, 控制台不是第二套事实
- 多网络组: 网络切换器 + 网络管理页, 各网络数据完全独立呈现

## 用户流程 / 页面结构

### 首次访问

1. 核心中继启动后, 浏览器访问其地址 (自签证书首次手动信任, 或配置域名走 ACME); 或本机执行 `kunxtier console --relay <核心地址>`
2. 使用 admin 凭证登录, 获得有过期时间的会话

### 日常管控

1. 网络切换: 顶部切换当前网络组, 全部页面随之切换; 网络管理页创建 / 列出网络组
2. 总览页: 当前网络的节点列表、在线 / 离线、路径与中继、版本信息
3. 节点详情: 属主标注、虚拟 IP、候选地址、路径策略开关; 支持按属主过滤
4. 令牌管理: 为用户签发一次性注册令牌 (明文仅展示一次)、撤销令牌; 为卫星签发可复用的 relay 注册令牌
5. 策略管理: 节点级强制中继开关
6. 中继管理: 卫星中继在线状态 (注册长连接存活)、地址、连接的节点数

## 功能要求

| 编号 | 说明 | 验收标准 |
| ---- | ---- | -------- |
| FR-1 | 总览实时反映全网节点状态与路径 | 与 `kunxtier status` / admin API 输出一致, 变化秒级可见 |
| FR-2 | 令牌签发与撤销 | 签发即生效可用于注册; 撤销后注册被拒; 明文仅展示一次 |
| FR-3 | 节点查看与移除: 展示属主标注并支持按属主过滤 | 操作需 admin 权限; 属主信息与核心数据一致 |
| FR-4 | 节点级强制中继策略配置 | 保存后经信令下发, 秒级生效, 与 feat-kunxtier-network FR-10 一致 |
| FR-5 | 卫星中继状态查看 | 展示在线 / 离线 (注册长连接)、地址、连接的节点数; 卫星断连后列表及时摘除 |
| FR-6 | 会话安全 | admin 凭证登录, 会话过期后需重新登录; 控制台与 API 同源 TLS |
| FR-7 | 控制台无状态 | 不落任何本地存储, 任意实例行为等价, 停止与重启不丢失管理数据 (数据全在核心中继) |
| FR-8 | 多网络组支持 | 网络切换器与网络管理页; 不同网络的成员与数据互不可见 |

## 边界与约束

- 轻量单页应用, 仅 admin 一种登录角色; 属主是展示标注, 无属主登录入口
- 无审批流: 令牌即授权, 设备凭令牌直接入网
- 浏览器范围: 现代 Chromium / Firefox / Safari, 不做旧浏览器兼容
- 本地起控制台的前提是该机器可达核心中继 admin API
- 前端源码位于 `web/kunxtier-console/`, 构建产物嵌入二进制, relay 托管与 console 子命令共用
- 总览页的路径与所用中继数据由节点经信令上报 (路径是节点本地状态, 核心不自行推断), 控制台只做展示
- `console --relay` 为本地进程托管页面并代理 admin API 的形态, 浏览器仅连接本地进程, 不直连核心 API
- ACME 随后续独立切片落地: 本阶段自签证书 + 浏览器首次信任是默认形态

## 非目标

- 属主 (普通用户) 登录与自助管理
- SSO 与双因素认证
- 多租户与管理员分级
- 审计报表与操作日志查询界面
- 原生移动端 App (移动浏览器自适应即可)
