# kunxtier 可观测性基线

## 背景

kunxtier 的典型运维模式是 "远程帮朋友排查为什么连不上"。打洞失败、路径切换、信令断连这类事件转瞬即逝, 没有留痕就只能靠复现。MVP 用最轻的手段保证关键事件可追溯: 分级结构化日志 + status 的排障视图, 不引入指标与追踪体系。

## 目标

- 所有关键路径事件有留痕, 且不泄露敏感值
- `kunxtier status --verbose` 能回答 "为什么这条链路走的是中继 / 为什么连不上"
- 日志级别与输出目标可配置, 默认配置即可用于日常排障

## 功能要求

| 编号 | 说明 | 验收标准 |
| ---- | ---- | -------- |
| FR-1 | 分级结构化日志 (error / warn / info / debug), 敏感值脱敏 | 脱敏规则与 nfr-kunxtier-security NFR-4 一致; 级别与输出目标 (stderr / 文件) 可配置 |
| FR-2 | 关键事件留痕: 打洞尝试与结果 (含失败原因: STUN 超时 / 候选交换失败 / 对端无响应)、路径切换 (direct 与 relay 互切)、信令断连与重连、注册与凭证校验失败、卫星注册与摘除 | 每类事件在日志中有稳定可检索的字段结构 |
| FR-3 | 排障视图: `kunxtier status --verbose` | 输出本机最近路径事件、当前对端的打洞失败原因与中继选择过程 |
| FR-4 | 核心中继侧事件留痕: 节点注册 / 凭证吊销 / 令牌校验失败 / 卫星注册与摘除 / admin 登录失败 | 可从日志还原一次接入或排障会话的完整时间线 |

## 边界与约束

- 日志为本地文件 / stderr, 不做远程收集
- debug 级别可能包含候选地址等网络拓扑信息, 但不包含任何凭证与密钥材料

## 非目标

- 指标体系 (metrics 栈) 与告警
- 分布式追踪
- 控制台内的日志查看界面
