# kunxtier 组网端到端测试

## 测试范围

覆盖 kunxtier MVP 核心闭环: 核心中继部署、令牌与凭证、三平台节点互通、直连 / 中继路径与策略、链路维持 (保活 / MTU)、卫星中继生命周期、网络组隔离、控制台双入口、服务化与数据迁移恢复。移动端不在范围内。

## 环境准备

| 项目 | 值 |
| ---- | --- |
| 核心中继 | 1 台节点可达的机器 (Linux, relay 验证平台), 部署 `kunxtier relay`, 开放 443/tcp (管理 + 信令 + 转发 + 控制台) |
| 卫星中继 | 1 个 `kunxtier relay --satellite` 实例 (独立机器, 或核心同机第二进程, 后者仅验证协议不验证隔离) |
| 客户端 A | macOS (本机), daemon + CLI |
| 客户端 B | Linux (可为同网段虚拟机), daemon + CLI |
| 客户端 C | Linux, 通过 iptables / nftables 限制仅允许与核心中继通信, 模拟打洞失败环境 |
| 客户端 D | Windows, daemon + CLI |
| 打洞验证组 E1 / E2 | 两台分别位于不同 NAT 后的 Linux 节点 (可用两套 network namespace + NAT 规则仿真, 或两台不同家庭网络机器), 验证真实受限锥形 NAT 打洞 |
| 网络组 | 默认网络 (init 自动创建) + 场景用第二网络组 net2 |
| 凭证 | 自签证书 + 指纹; admin 凭证一份; relay 注册令牌一份; 一次性注册令牌按场景准备 |
| 浏览器 | 现代 Chromium / Firefox / Safari 任一 |

## 场景矩阵

| 场景 | 前置条件 | 操作 | 预期结果 |
| ---- | -------- | ---- | -------- |
| 核心中继初始化 | 机器就绪 | `kunxtier relay --init` 后启动 | 生成 state 目录与证书, 权限 0600; 443 可达; 默认网络组已创建 |
| 令牌注册设备 | 核心在线, 令牌有效 | 客户端 `kunxtier up --token ... --name a` | 注册成功, 分配 /32, 获得节点凭证; 同一令牌二次注册被拒 |
| 同名注册被拒 | 已有节点 `a` | 另一设备用 `--name a` 注册 | 注册被拒, 错误提示名字冲突 |
| 节点移除后旧凭证失效 | 节点 a 在线 | admin 移除 a 后, a 的 daemon 尝试重连 | 信令被拒 (凭证已吊销), 网内流量停止 |
| 禁用用户 | 用户 u 名下有在线设备 | admin 禁用 u | 其设备凭证被吊销、重连被拒, u 的令牌全部失效 |
| 令牌暴力限速 | 核心在线 | 脚本连续提交错误令牌注册 | 达到阈值后被限速 / 退避, 返回明确错误, 正常客户端不受影响 |
| 双节点直连 (真实 NAT) | E1、E2 分别在不同 NAT 后 | E1 ping E2 虚拟 IP | 打洞建立直连, status 显示 direct, 延迟为直连量级 |
| 打洞失败回落中继 | C 被限制仅通核心 | A 与 C 互 ping | 自动回落 (先核心内置转发), status 显示 relay, 业务可用 |
| 卫星中继注册 | relay 令牌有效 | 另起 `kunxtier relay --satellite` 注册 | 中继列表自动更新并分发, 节点无需重启即可使用卫星 |
| 卫星下线摘除 | 卫星已注册, 有节点经它回落 | 杀掉卫星进程 | 列表及时摘除, 回落流量切换到下一中继或核心内置转发 |
| 强制中继策略 | A、B 当前直连 | 控制台对 A 设置强制中继 | A 不再打洞, 全部流量走中继; 取消设置后恢复 direct |
| 空闲保活 | A、B 直连 | 保持 30 分钟无流量后 ping | 首包即通, 路径仍为 direct, 无重新打洞痕迹 |
| MTU 大包 | A、B 分别处于直连与中继路径 | `ping -s 1400` 与大文件 TCP 传输 | 两种路径下均无异常丢包或挂死 |
| 本地网段冲突 | 节点本机路由含所属网络 /16 的地址 | 启动 daemon | 拒绝启动, 输出诊断与处理建议 |
| Windows 节点互通 | D 注册在线 | D 与 A、B 互 ping | 互通成功, 路径与 status 显示一致 |
| daemon 服务化 | A 或 D 已 `kunxtier install` | 重启机器 | daemon 自动恢复上线, 无需人工登录执行 |
| daemon 未运行提示 | daemon 未启动 | 执行 `kunxtier status` | 明确提示 daemon 未运行与启动方式, 不报晦涩错误 |
| 控制台 (核心托管) | 核心在线 | 浏览器打开核心地址并登录 | 总览状态与 CLI / API 一致; 令牌签发与撤销可用 |
| 控制台 (console 子命令) | 核心在线 | 本机 `kunxtier console --relay` 后浏览器打开本地地址 | 与核心托管入口行为等价, 无本地管理数据落盘 |
| 控制台会话过期 | admin 已登录 | 等待会话过期后操作 | 要求重新登录, 无越权残留 |
| admin API 鉴权边界 | 持有某节点凭证 | 用节点凭证调用 admin API | 被拒绝, 凭证类型不互通 |
| 跨用户互通 | A、C 属不同用户 | A ping C | 互通成功 (全互通模型) |
| 属主标注与过滤 | 多属主节点在线 | 控制台按属主过滤节点列表 | 过滤结果正确; 属主为展示标注, 无属主登录入口 |
| 网络组隔离 | A 在默认网络, B 注册进 net2 | 默认网令牌尝试注册进 net2; A ping net2 内节点 | 令牌跨网被拒; 跨网 ping 不通; 控制台内两网数据互不可见 |
| 网络组管理 | admin 已登录 | `admin network create` 后控制台切换到新网 | 新网出现在切换器, 可立即签发令牌, 无需重启核心中继 |
| 节点下线 | B 在线 | B 执行 `kunxtier down` | A 的节点表秒级移除 B, ping 失败 |
| 核心中继重启 | 全网在线 | 重启 relay 进程 | 节点与卫星自动重连, 互通恢复, IP 不变 |
| 备份与恢复 | 全网在线且有历史数据 | `kunxtier relay backup` 后在新机恢复并启动 | 网络组、用户、节点、令牌状态完整还原, 节点重连即恢复 |
| 旧版本升级 | 使用旧 schema 的数据库 | 新版本二进制启动 | schema 自动前向迁移, 数据完整, 全网恢复 |
| 令牌撤销 | 令牌已签发未使用 | admin 撤销后尝试注册 | 注册被拒绝, 错误信息明确 |
| 恶意指纹 | 客户端配置了错误的核心指纹 | `kunxtier up` | 连接被拒绝, 提示指纹不匹配 |

## 关键用例

### 打洞失败回落中继

1. 客户端 C 配置防火墙, 仅放行与核心中继的通信
2. A 与 C 分别 `kunxtier up` 上线
3. A 执行 `ping <C 虚拟 IP>` 持续 60 秒
4. 期间观察 A 的 `kunxtier status` 与控制台总览

预期结果:

- 打洞超时窗口内完成向中继的回落, ping 恢复连通
- status 与控制台中 C 的路径均显示 relay
- 全程无人工干预, 无 daemon 崩溃或重启

### 真实 NAT 打洞直连 (E1 / E2)

1. E1、E2 分别在不同 NAT 后上线
2. `kunxtier status --verbose` 观察打洞过程日志
3. E1 持续 ping E2 并发起 TCP 业务

预期结果:

- status 显示路径为 direct, verbose 日志含 STUN 探测与候选交换记录
- 打洞成功后业务直连量级延迟, 且空闲 30 分钟后不回退

### 强制中继策略生效与恢复

1. A 与 B 处于直连状态, 业务流量正常
2. 控制台对 A 打开强制中继开关
3. 持续 ping B, 观察 A 的 status
4. 关闭开关, 继续观察

预期结果:

- 开关生效后 A 的流量全部经中继, 路径显示 relay, 秒级切换, 业务不中断
- 关闭后 A 恢复直连 (重新打洞), 路径回到 direct

### 核心中继重启恢复

1. A、B、C、D 全部在线且互通, 卫星中继已注册
2. 重启核心中继进程
3. 观察各节点与卫星的信令重连与互通状态

预期结果:

- 节点与卫星在重试窗口内自动重连信令通道
- 既有直连会话在核心中继重启期间不中断
- 恢复后新连接可建立, 节点表、中继列表与虚拟 IP 不变

## 不测范围

- 吞吐与并发压测 (后续 perf 文档承接)
- 移动端平台; 一个节点同时加入多个网络 (多 membership)
- relay 在 macOS / Windows 上的运行 (MVP 验证环境为 Linux)
- 子网路由 / 出口网关 (后续阶段功能)
- 控制台前端 UI 细节与浏览器兼容矩阵 (仅冒烟覆盖)
- 令牌并发签发的极端竞态
