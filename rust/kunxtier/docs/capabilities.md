# 能力边界与路线图

本文列出 kunxtier 当前具备的能力与明确不做的边界。
选型或组网前先读本文, 避免依赖尚未实现的能力。

## 状态分档

- **已验证**: 代码已实现,
  且通过单元测试与单机端到端场景验证
- **待真机验证**: 代码已实现,
  缺真实 NAT / 公网 / 生产环境的验证
- **进行中**: 已立项开发, 行为可能变化
- **未实现**: 规划中或明确列入非目标, 不可依赖

## 已验证的能力

- **组网数据面**: STUN 地址探测, 并发打洞,
  打洞超时自动回落中继, 直连恢复切换
- **NAT 适应性**: CGNAT 网段与虚拟网段冲突检测;
  强制中继策略可按节点设置
- **连通性保活**: 对端 ping 间隔 15 秒,
  60 秒无响应判定失联
- **信令**: WebSocket 信令通道, 注册挑战应答,
  节点表与密钥分发
- **中继转发**: 核心内置转发与卫星纯转发双模式,
  卫星列表动态分发与断连摘除
- **令牌体系**: 一次性节点令牌, 可复用卫星令牌,
  节点凭证挑战应答, admin 凭证
- **管理 API**: 指纹固定 HTTPS 的 REST 接口,
  网络组 / 用户 / 令牌 / 节点四域管理
- **Web 控制台**: 网络组 / 节点 / 令牌等管理页面,
  嵌入核心或本地反代两种入口
- **CLI**: relay / admin / daemon / up / down / status /
  console / config / install 全命令面
- **服务化**: macOS launchd 与 Linux systemd 注册开机自启
- **备份**: SQLite 一致性快照导出, schema 版本自动迁移
- **可观测**: 结构化日志 (text / json), 关键事件留痕,
  `status --verbose` 排障视图

## 待真机验证的能力

| 能力 | 现状 |
|---|---|
| 真实 NAT 打洞 | 单机双 daemon 已验证, 跨公网未验证 |
| 卫星中继 | 注册分发逻辑已实现, 公网真机未验证 |
| systemd 生产托管 | 注册逻辑已实现, 长期运行未验证 |
| 断电重启自愈 | 恢复路径已实现, 真机断电未验证 |

## 进行中

- **用户模型移除**: 现有 "用户 (属主)" 概念将被整体移除。
  届时 `admin user` 子命令、用户相关 API 与
  控制台用户界面会同步调整。
  过渡期内按本文档使用, 不建议围绕用户模型二次开发。

## 未实现的能力

### 平台

- **Windows**: 全平台未支持。
  TUN 适配、本地 IPC、服务注册均为占位实现,
  执行 `install` 直接报错
- **移动端**: iOS / Android 无客户端

### 网络

- **IPv6**: 虚拟网仅 IPv4, IPv6 数据面未实现
- **子网路由**: 虚拟网内访问物理网段未实现
- **出口网关**: 流量经某节点公网出口转出未实现
- **DNS**: 虚拟网内域名解析管理未实现
- **二层仿真**: 桥接 / 组播 / 广播未实现, 仅三层转发
- **ACL**: 节点间访问控制未实现, 网络组内默认互通
- **多 membership**: 一节点同时入多个网络组未实现
- **多核心 HA**: 多核心互备未实现, 核心为单点
- **网络组删除**: 管理面只能创建网络组, 不能删除

### 证书与运维

- **ACME**: 不支持自动申请公共信任证书,
  仅自签证书 + 指纹固定
- **备份调度**: `relay backup` 为手动导出, 无定时自动备份
- **metrics**: 指标暴露与分布式追踪未实现,
  观测依赖日志与事件
